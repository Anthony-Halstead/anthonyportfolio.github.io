Untitled FPS – Large Scale Combat Prototype

Unity FPS C#

🎯 Project Overview

Untitled FPS is a first-person shooter prototype built in Unity that focuses on traditional FPS combat in a large outdoor environment. The core loop combines moment-to-moment gunplay with objective-based progression across a sizeable level, with enemy encounters paced around key landmarks and routes.

I treated this project as a sandbox for learning FPS fundamentals in Unity: combat feel, encounter design, AI behavior, and performance-aware level layout. :contentReference[oaicite:0]{index=0}

🧩 The Problem

The design problem was essentially:

“How do you build a readable, performant FPS level with AI-driven encounters and objective flow, using Unity, in a way that scales to a large environment without overwhelming the player or the engine?”

Key challenges:

  • Designing a large, explorable space that still funnels players through meaningful combat beats
  • Building a flexible spawn system that can drive encounters without hard-coding every enemy
  • Creating AI that can navigate, engage, and pressure the player without feeling unfair
  • Keeping performance stable as enemy counts and view distances increase

🛠️ What I Built

  • Level layout & encounter pacing – Blocked out the main environment and tuned sightlines, cover, and traversal routes to create distinct combat pockets (open fields, chokepoints, flanking paths).
  • Spawn & wave system – Implemented a spawn controller that supports:
    • Configurable spawn points and groups tied to objectives or triggers
    • Waves that can escalate based on player progress
    • Simple knobs for iteration (enemy counts, delays, composition)
  • AI & boss behavior – Built enemy and boss behaviors including:
    • Basic state-based logic (patrol, chase, attack, search)
    • Ranged combat with line-of-sight checks and simple cover usage
    • Boss behavior tuned to force movement and use of the arena space
  • Gameplay feel & tuning – Iterated on weapon feel (rate of fire, recoil, damage tuning), hit feedback, and time-to-kill to keep combat readable and responsive.
  • Performance & stability passes – Profiling-driven clean-up:
    • Reduced unnecessary updates on enemies when off-screen or inactive
    • Adjusted spawn counts and distances to keep framerate smooth during heavy combat

🎮 Design & Technical Principles

  • Readable combat spaces – Clear silhouettes and cover placement so players quickly understand where threats are coming from and where they can reposition.
  • Encounter-first level design – Built the environment around specific fights rather than dropping enemies into a generic space.
  • Iterative tuning – Used quick iteration loops on spawn timings, enemy health, and player damage to get the “feel” right before adding extra content.
  • Scalability – Structured the spawn system so new encounters can be added via data rather than new code whenever possible.

✅ Outcome

  • Delivered a playable FPS prototype with objective-driven progression across a large environment
  • Demonstrated ability to own both level design and core gameplay programming for an FPS
  • Created a foundation that could be extended into a more complete campaign or wave-based mode

⚙️ Tools & Technologies

  • Unity (URP), C#
  • Unity physics, collision, and basic character controller-style movement
  • Simple spawn management and AI logic implemented in C# scripts
  • GitHub for source control and iteration history

Murder At Hollowstone Manor – Mystery Puzzle Game

Unity Puzzle 3D C#

🎯 Project Overview

Murder At Hollowstone Manor is a light-hearted first-person mystery/puzzle game built in Unity. The player explores an old manor, investigates a murder, finds clues, and ultimately reports to the police who they believe committed the crime. The focus is on approachable puzzle design, readable UI, and a tightly scoped detective loop that can be completed in a single sitting.

🧩 The Core Experience

The game is built around a simple question: “Can we make a short, replayable mystery experience where players feel like they’re actually piecing together a case, rather than just following objective markers?”

Core pillars:

  • Exploration of a small but dense manor environment
  • Puzzles that are readable without heavy tutorials
  • A clue system that tracks player discoveries in-game
  • A final accusation moment where the player commits to their theory

🛠️ My Contributions

  • Level Design – Blocked out and iterated on the manor layout to support a natural investigation path, backtracking, and sightlines that guide the player without explicit waypoints.
  • Puzzle System – Designed and implemented the core puzzle framework in C#, including interaction logic, state tracking, and feedback for success/failure.
  • All In-Game Puzzles – Authored the individual puzzles (locks, combinations, environmental clues), including hint structure and how each one ties into the overall case.
  • Clue System & UI – Built the clue log UI that records key discoveries, making it easy for players to review suspects, motives, and evidence before making their final choice.
  • Inventory System – Implemented a lightweight inventory for holding keys, evidence items, and puzzle components, with tooltip support and basic categorization.
  • Crafting System – Added a small crafting layer for combining certain items (e.g., assembling evidence or tools) to reinforce the “detective work” fantasy.
  • Opening Cinematic & Main Menu UI – Built the intro sequence that sets up the murder, handled camera scripting, timing, and transitions into the playable scene, plus the main menu and options layout.

🎮 Design & Technical Details

  • Interaction system based on raycasts and tagged interactables, supporting context-sensitive prompts and highlight states.
  • Data-driven puzzle configuration using ScriptableObjects (puzzle parameters, combinations, required items).
  • Modular UI panels for inventory, clues, and pause/options so they can be repurposed for future projects.
  • Simple state machine for the overall case flow (investigating → clue gathering → accusation → resolution).
  • Use of post-processing, lighting, and audio cues to subtly direct player attention to important rooms and objects.

✅ Outcome

  • Delivered a complete, playable mystery experience with a full start-to-finish loop.
  • Showcased my ability to own both systems design (puzzles, inventory, clue tracking) and player-facing UX (UI, flow, feedback).
  • Provided a strong portfolio piece demonstrating Unity gameplay code, level design sensibilities, and UI implementation working together.

⚙️ Tools & Technologies

  • Unity (3D pipeline, scene management, lighting)
  • C# (interaction system, puzzles, inventory, UI logic)
  • Unity UI Toolkit / UGUI for menus, clue log, and in-game HUD
  • Git / GitHub for version control and collaboration

Renegade – Top-Down Bullet Hell (Custom Engine)

Custom Engine C C++ Vulkan Bullet Hell

🎯 Project Overview

Renegade is a fast-paced top-down bullet hell built on a custom C/C++ engine using Vulkan for rendering. The goal of the project was to ship a complete arcade-style experience while building out real engine systems: rendering, audio, level loading, and AI behavior, instead of relying on an off-the-shelf engine.

The game focuses on tight boss encounters, dense projectile patterns, and responsive player controls, all driven by systems that were designed and implemented at the engine level.

🧩 The Problem

The core question behind Renegade was:

“How can we build a small but complete custom engine that supports an arcade bullet hell—rendering, audio, level logic, and AI—while still being maintainable, debuggable, and performant enough to handle heavy projectile patterns and boss behaviors?”

Key challenges:

  • Integrating Vulkan-based rendering in a way that stayed flexible for 2D/“top-down” style visuals
  • Designing a data flow that cleanly separated engine systems from game logic
  • Implementing a dynamic audio system that responded to gameplay states (boss phases, damage, victory, etc.)
  • Authoring boss and enemy behaviors without a full editor stack
  • Managing many simultaneous projectiles and boids without frame hitches

🛠️ What I Built

  • Engine texture integration – Implemented texture loading and management in the engine, including:
    • Texture resource creation and lifetime handling for Vulkan
    • Basic sprite/quad rendering pipeline for top-down assets
    • Support for multiple texture assets (player, enemies, UI, backgrounds)
  • Engine shader integration – Wired up the Vulkan shader pipeline:
    • Shader module loading/compilation and pipeline state setup
    • Simple but clean material/shader parameter flows for sprites and effects
    • Configuration to support different render passes (gameplay, UI)
  • Engine level integration – Built the basic level logic layer:
    • Level data integration (spawn timing, enemy waves, boss entry)
    • Scene update loop that ties together input, AI, physics-lite motion, and rendering
  • Dynamic audio system – Integrated the engine audio layer and tied it to game state:
    • Support for music + SFX channels and simple mixing
    • Events for boss phases, player hit, death, and victory states
    • Reactive audio feedback for bullet patterns and high-intensity moments
  • AI & boss systems – Implemented enemy and boss logic:
    • Boss phase system with distinct patterns per phase
    • Pattern-based projectile emission for bullet hell attacks
    • Basic state-driven behavior for movement, aggression, and vulnerability windows
  • Boid system for flocking agents – Implemented flocking enemies:
    • Steering behaviors (cohesion, separation, alignment-style logic)
    • Integration with bullet patterns to create “screens full” of moving threats
    • Performance-conscious updates to keep flock movement smooth

🎨 Design & Technical Principles

  • Engine-first thinking – Every feature (AI, bullets, audio) was treated as a system plugged into a clean engine loop.
  • Deterministic, pattern-based combat – Enemy and boss attacks are predictable but challenging, encouraging learning and mastery.
  • Responsiveness over complexity – Controls and feedback were prioritized, especially hit reactions, damage cues, and clarity of projectiles.
  • Debuggability – Code was structured to make it straightforward to change patterns, timing, and enemy behaviors without a full editor.

✅ Outcome

  • Delivered a playable, complete bullet hell experience on top of a custom C/C++ engine.
  • Demonstrated practical Vulkan rendering integration in a game context.
  • Built a foundation engine that could be extended with additional levels, patterns, or tools.
  • Provided a strong portfolio example of low-level engine work plus gameplay systems (AI, audio, level flow).

⚙️ Tools & Technologies

  • Custom C / C++ game engine
  • Vulkan rendering API
  • Custom texture, shader, and level integration systems
  • Custom audio system (music + SFX, state-driven)
  • GitHub for version control and collaboration

MeshForge – Modular Character Editor

Unity Tools

🎯 Project Overview

MeshForge is a Unity editor toolkit for turning existing skinned and static meshes into modular, reusable building blocks. It’s aimed at developers and technical artists who don’t live in DCC tools all day, but still need flexible character and environment modularity. The suite bundles several tightly integrated tools—Mesh Rebaker, Splitter, Gap Filler, Skinned Mesh Combiner, and the newer Topology Splitter—into a non-destructive workflow that runs entirely inside the Unity Editor.

The asset is compatible with Unity 2021 LTS through Unity 6, supports all major render pipelines, and has been iteratively shipped and updated on the Unity Asset Store (v1.2.0 as of April 2025).

🧩 The Problem

Most small teams and solo devs don’t have time to constantly go back into Blender/Maya just to test a new armor variant, swap a character’s head, or break a static mesh into modular kit pieces. I built MeshForge to answer:

“How can Unity developers quickly modularize skinned and static meshes—without deep 3D modeling skills—while preserving rigging, materials, and animation fidelity, and keeping the workflow safe and non-destructive?”

Key challenges:

  • Preserving skin weights, bone influences, and animation behavior when splitting skinned meshes
  • Handling meshes with multiple submeshes and materials without breaking existing setups
  • Supporting both skinned and static meshes in a single, coherent workflow
  • Filling open gaps cleanly while keeping UVs and materials consistent
  • Keeping everything non-destructive so artists never have to re-import “ruined” assets
  • Designing algorithms that can later be migrated to Jobs/Burst for future runtime use
  • Maintaining compatibility across multiple Unity versions and render pipelines

🛠️ What I Built

  • Mesh Rebaker – Rebuilds meshes into Unity’s coordinate space from a prefab reference, giving cleaner, predictable geometry as a foundation for further edits.
  • Splitter – Core tool that splits both skinned and static meshes into modular parts. For skinned meshes it:
    • Extracts each logical part into its own skinned mesh while preserving skin weights and animation behavior
    • Supports submesh extraction so material assignments remain intact
    • Includes experimental deformation options to resize parts to match different character scales (e.g., small → large rigs)
  • Gap Filler – Fills holes left after splitting by selecting boundary vertices and procedurally generating new triangles. Supports “fan” (flat) and convex fill modes, reusing the original material or a user-specified override.
  • Skinned Mesh Combiner – Recombines previously split parts back into a single skinned mesh. Useful for baking down finalized variants or reducing draw calls after experimentation.
  • Topology Splitter (v1.2.0) – A topology-aware static mesh splitter that analyzes connected components and lets users group, merge, and cap specific parts. This is especially useful for environment meshes and intricate props.
  • Non-destructive workflow – All operations work on instances or duplicated assets, keeping the original files intact so users can experiment freely without re-importing content.
  • Editor-focused UX – Contextual inspector UI, drag-select support, and clear feedback for long-running operations; plus documentation, tutorial videos, and a Discord community for support.

🎨 Technical & Design Principles Applied

  • Topology-driven operations – Many features are built around understanding mesh connectivity so that parts can be separated or grouped in predictable, artist-friendly ways.
  • Data-preserving edits – Careful handling of vertex indices, bone weights, bindposes, and UVs to maintain animation fidelity and texture alignment after splitting or filling.
  • Non-destructive editor tooling – All tools are designed so they never overwrite the source asset, encouraging experimentation and iteration without fear of losing work.
  • Performance-aware architecture – Core algorithms are structured to be portable to Unity’s C# Job System and Burst compiler so that future runtime variants can scale to larger scenes and more complex meshes.
  • Robust version & pipeline support – Targeting Unity 2021 LTS–Unity 6 with attention to editor API changes (e.g., drag-select behavior differences in pre-2022 versions) and compatibility with Built-in, URP, and HDRP.

✅ Outcome

  • Shipped MeshForge as a production-ready Unity Editor extension on the Unity Asset Store, iterating up to v1.2.0 with new features like Topology Splitter and improved static mesh support.
  • Enabled developers to convert existing character and environment assets into modular kits without needing to open a DCC tool, improving iteration speed for prototyping, customization, and content variation.
  • Built a toolset that is already in active use by other Unity developers and favorited by multiple users on the store, providing a concrete example of a shipped, maintained, commercial-grade tool.
  • Established a foundation for future runtime mesh operations (splitting, filling, and morphing) informed by real-world user feedback through documentation, tutorials, and a dedicated Discord community.

⚙️ Tools & Technologies

  • Unity Editor (2021 LTS – Unity 6, Built-in / URP / HDRP)
  • C# (editor tooling, mesh manipulation, custom inspector workflows)
  • Unity’s Mesh, SkinnedMeshRenderer, and ScriptableObject APIs
  • Prefabs & asset pipeline integration for safe, non-destructive editing
  • Git / GitHub for version control and release management
  • Unity Asset Store for distribution, updates, and user feedback

Hierarchical Tag Forge – Gameplay Tag Framework

Unity Tools

🎯 Project Overview

Hierarchical Tag Forge is a production-grade, Unreal-style hierarchical gameplay tag framework for Unity. It gives a project one consistent, dot-separated vocabulary (for example, Ability.Magic.Fire.Fireball) that can be shared across abilities, AI states, items, units, weapons, buffs and debuffs, events, UI flows, and quest flags—while keeping runtime lookups fast, deterministic, and scalable as content grows.

Instead of relying on fragile string comparisons, scattered enums, and one-off manager scripts, teams maintain a centralized Gameplay Tag Database and query it at runtime through access patterns designed for real game workloads. The asset targets Unity 2022 LTS through Unity 6, supports Built-in, URP, and HDRP, has no third-party runtime dependencies, and is available on the Unity Asset Store (v1.0.1 as of February 2026).

🧩 The Problem

Unreal developers get a Gameplay Tag system out of the box. Unity developers usually end up rebuilding one for every project with string tags, bloated enums, and ad-hoc “manager” scripts that don’t scale, aren’t designer-friendly, and allocate garbage in the hottest code paths. I built Hierarchical Tag Forge to answer:

“How can Unity developers describe what things are and what they can do with a single hierarchical, designer-friendly vocabulary—and evaluate those rules thousands of times per frame without garbage collection or fragile string comparisons?”

Key challenges:

  • Giving every tag a stable identity that survives renames and rebakes while still enabling fast integer-based hierarchical matching at runtime
  • Keeping steady-state queries—single tags, Any/All checks over containers, and compiled boolean queries—allocation-free so they are safe for AI, combat, and per-frame UI gating
  • Supporting exact and hierarchy-aware matching (IncludeDescendants / IncludeAncestors) with predictable, documented semantics
  • Letting designers author nested AND/OR/NOT logic without bespoke code, while guaranteeing the compiled runtime data never drifts from the authored definition
  • Failing closed when hierarchy data isn’t loaded so a descendant match can never silently become an overly broad match
  • Making the full author → bake → generate → validate workflow robust enough for team pipelines and CI
  • Delivering editor UX that scales to large vocabularies: searchable pickers, inline comments, and clear cues for missing, stale, or invalid data

🛠️ What I Built

  • Gameplay Tag Database & Tag Manager – A centralized ScriptableObject database edited through a dedicated Tag Manager window with a searchable hierarchical tree, expand/collapse, inline comments that double as a tag glossary, add-subtag / rename / delete-with-children actions, and automatic creation of missing parent segments.
  • Baking & code generation – Baking converts the editable database into runtime-friendly data: deterministic integer IDs, parent chains, and lookup tables. An optional generator emits a strongly typed, runtime-safe C# class of tag constants for typo-proof references, and tags can also be declared in code with a HierarchicalTag attribute that is discovered at bake time.
  • Core runtime value types – GameplayTag (a GUID-backed single-tag handle), GameplayTagContainer (a canonical sorted, de-duplicated tag set with exact and hierarchical matching), GameplayTagQuery (an authored definition tree compiled into deterministic runtime buffers), and GameplayTagRequirements (a GAS-style gate combining RequireAll / RequireAny / BlockAny plus an optional query, evaluated in short-circuit, fail-fast order).
  • Editor tooling – Custom property drawers for every type, a Tag Picker dropdown with single-select and multi-select modes, and a dedicated Query Editor window for building nested group / leaf / constant node trees with validation, orphan pruning, and auto-compile.
  • Runtime ownership & utilities – A GameplayTagOwner component exposing query and mutation APIs plus change notifications (C# events and UnityEvents with Added/Removed diffs), and GameplayTagAssetUtility for querying or mutating tags on any UnityEngine.Object through strict and “safe” query families.
  • Reusable content assets – GameplayTagQueryAsset and GameplayTagRequirementsAsset wrap queries and rulesets as drag-and-drop ScriptableObjects so designers can share gating logic across abilities, interactables, and UI.
  • Validation & diagnostics – Project Settings with recommended and strict presets, a build-time validator that detects (and optionally auto-fixes) stale compiled queries across prefabs, ScriptableObjects, and build scenes, and a Stress Harness that benchmarks each query path under load with Unity Profiler markers.
  • Demo scene & documentation – Copy-ready template scripts for tag owners, callers, queries, and requirement gates, a comprehensive user manual, and video tutorials.

🎨 Technical & Design Principles Applied

  • GUID-first identity, integer-fast evaluation – Authored tags are identified by stable GUIDs; baked integer IDs and parent chains are treated as a rebuildable cache, so renames and rebakes never break references.
  • Zero-GC steady state – Value-type containers, ref-based query overloads, reusable temporary containers, and linear merge-walk diffs over sorted GUID arrays keep steady-state queries and bulk mutations allocation-free.
  • Authoring / runtime separation – Queries are edited as human-readable definition trees and compiled into deterministic node buffers, with a definition hash to detect staleness and tooling that keeps both in sync.
  • Fail-closed safety – Hierarchical checks return false rather than guessing when the registry isn’t initialized, and “safe” query variants degrade to exact matching, preventing accidental broad matches in production.
  • Data-driven, designer-facing rules – Requirements, queries, and tag sets are serializable assets with descriptions and Inspector status lines, reducing tribal knowledge and one-off gameplay scripts.
  • Pipeline-aware tooling – Selection-driven menu commands, project-scoped settings that can be committed to source control, and build validation policies (fail on stale / auto-fix) designed for teams and CI.

✅ Outcome

  • Shipped Hierarchical Tag Forge on the Unity Asset Store (v1.0.1, February 2026) with Unity 2022 LTS – Unity 6 support, Built-in / URP / HDRP compatibility, and no third-party dependencies.
  • Gives Unity teams an Unreal-style hierarchical vocabulary that designers author in the Inspector and programmers reference through generated constants, instead of per-project string and enum systems.
  • Delivered a performance story teams can verify themselves: allocation-free steady-state query paths plus a bundled Stress Harness with profiler markers for benchmarking on target hardware.
  • Backed the release with a full user manual, a demo scene of copy-ready templates, video tutorials, and direct developer support—establishing CarryForge’s second commercial Unity tool alongside MeshForge.

⚙️ Tools & Technologies

  • Unity 2022 LTS – Unity 6 (Built-in / URP / HDRP)
  • C# (struct-based runtime types, allocation-conscious APIs, ref-based query overloads)
  • Unity Editor tooling: IMGUI editor windows, custom PropertyDrawers, TreeView-based pickers, Project Settings integration, menu commands
  • ScriptableObject databases, managed references for query definition trees, Resources-based runtime settings
  • Editor-time code generation (strongly typed tag constants) and attribute-based tag declaration via TypeCache
  • Build-time validation pipeline and Unity Profiler markers for diagnostics
  • Git / GitHub for version control and release management
  • Unity Asset Store for distribution, updates, and user feedback
